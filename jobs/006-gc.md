Job 006 — Garbage Collector

Objective

Implementasikan Garbage Collector (GC) untuk ZeroVM menggunakan pendekatan tracing mark-and-sweep.

---

GC Model

Gunakan tracing garbage collector dengan pendekatan mark-and-sweep.

Jangan menggunakan "Rc<T>" / "Arc<T>" sebagai mekanisme ownership/GC utama ZeroScript.

Rust ownership hanya digunakan untuk struktur internal implementation Rust. Lifetime object ZeroScript ditentukan oleh reachability pada heap ZeroScript.

GC harus mampu menangani object graph yang memiliki cycle.

Roots
  │
  ▼
Mark reachable objects
  │
  ▼
Sweep unreachable objects

---

Root Set

Gunakan root yang memang tersedia atau diwajibkan oleh architecture/spec.

Root dapat mencakup:

- value stack
- active execution frames / call frames
- global/runtime values
- closure environments jika sudah tersedia
- root lain yang secara eksplisit ditentukan oleh spec

Jangan mengarang root baru hanya untuk mempermudah implementasi.

Jika suatu subsystem belum tersedia, buat abstraction yang memungkinkan integrasi kemudian tanpa mendesain ulang GC.

---

Mark Phase

Mark seluruh object yang reachable dari root dan trace reference secara transitif sampai seluruh object reachable telah ditemukan.

Contoh:

Root
 │
 ▼
A
├──► B
│    └──► C
└──► D

A, B, C, dan D harus survive.

Cycle juga harus ditangani dengan benar.

---

Sweep Phase

Setelah marking:

- object marked → tetap
- object unmarked → collected
- metadata heap diperbarui secara konsisten
- reference yang menunjuk object yang sudah collected menjadi invalid

GC tidak boleh mempertahankan unreachable cycle hanya karena object-object tersebut saling mereferensikan.

---

Heap Integration

Gunakan Heap dan RuntimeValue hasil Job 005.

Jangan membuat sistem Heap kedua.

Jangan mengganti architecture Job 005 secara besar-besaran tanpa alasan yang kuat.

Jika API internal perlu diubah, pertahankan compatibility dengan seluruh existing tests.

---

RuntimeValue Integration

Primitive:

Number
Boolean
Null

tidak membutuhkan tracing.

Heap-backed values harus ditrace sesuai representasi runtime aktual, termasuk bila tersedia:

String
List
Object
Function
Closure / environment

Jangan mengasumsikan object memiliki child reference jika representasi aktualnya tidak demikian.

---

Invalid References

Akses terhadap "HeapRef" yang sudah tidak valid harus menghasilkan error yang sesuai dengan sistem error yang ada.

GC tidak boleh menyebabkan:

- Rust panic
- use-after-free
- dangling Rust reference
- undefined behavior

Hindari "unsafe" kecuali benar-benar diperlukan dan dapat dijustifikasi.
